# 规格文档审阅者提示模板

在派遣规格文档审阅者subagent时使用此模板。

**目的：** 验证规格是完整的、一致的，并准备好进行实现计划。

**派遣时机：** 规格文档已写入 docs/superpowers/specs/ 之后

```
Task 工具（通用）：
  description: "审阅规格文档"
  prompt: |
    你是一位规格文档审阅者。验证此规格是否完整并准备好制定计划。

    **待审阅的规格：** [SPEC_FILE_PATH]

    ## 检查内容

    | 类别 | 关注点 |
    |----------|------------------|
    | 完整性 | TODO、占位符、"TBD"、不完整的部分 |
    | 一致性 | 内部矛盾、冲突的需求 |
    | 清晰度 | 足够模糊以至于可能让人构建出错误内容的需求 |
    | 范围 | 足够聚焦于单一计划——不涵盖多个独立子系统 |
    | YAGNI | 未被要求的功能、过度工程 |

    ## 校准

    **只标记那些在实现计划期间会导致真实问题的问题。**
    缺失的部分、矛盾、或者模糊到可以有两种不同解读的需求——这些才是问题。轻微的措辞改进、
    风格偏好和「某些部分不如其他部分详细」不是问题。

    除非存在会导致计划出错的严重缺陷，否则予以批准。

    ## 输出格式

    ## 规格审阅

    **状态：** 已批准 | 发现问题

    **问题（如有）：**
    - [第 X 部分]：[具体问题] - [为什么对计划重要]

    **建议（仅供参考，不阻止批准）：**
    - [改进建议]
```

**审阅者返回：** 状态、问题（如有）、建议
