# 翻译 Skills

## 概述

将英文 skill 目录批量翻译为中文，同时保留代码、命令和技术术语的正确性。通过并行 subagent 分派实现高效翻译和审查。

**核心原则：** 翻译前确定规则，翻译后必须审查，修复后必须验证。

## 翻译规则

### 必须翻译

- 所有自然语言正文（段落、列表项、表格单元格内容）
- 章节标题
- 代码示例的配套评注（如 `<Good>` / `<Bad>` 后的说明文字）
- YAML frontmatter 的 `description` 字段值
- 流程图中的人类可读标签（dot/graphviz 节点标签）

### 不得翻译

- YAML frontmatter 的 `name` 字段（程序标识符，用于 `Skill("name")` 调用）
- 代码块（bash、typescript、python、json、jsonl 等）内容
- 文件路径、URL
- dot/graphviz 语法结构（`digraph`、`shape`、`label=` 关键词和引号内不变）
- `<HARD-GATE>`、`<Good>`、`<Bad>`、`<SUBAGENT-STOP>` 等标记标签

### 技术术语处理

翻译开始前，**必须先读取** `terms-to-keep.md`（与本文件同级目录）获取完整的保留术语清单。中文技术语境下广泛使用的英文词**保留原样**。

在 subagent 的翻译提示中，明确列出不得翻译的术语清单，确保所有 translator 遵守相同规则。

专业术语首次出现时建议括号注明英文原文，后续出现仅保留中文。

### 跨文件一致性

翻译全程必须保持下列关键概念的翻译统一：

| 英文原文 | 统一中文译文 |
|---------|------------|
| your human partner | 你的人类伙伴 (your human partner) |
| Red Flags | 红旗信号 (Red Flags) |
| Iron Law | 铁律 |
| Violating the letter is violating the spirit | 违反规则的字面要求，就是违反规则的精神 |
| Core principle | 核心原则 |
| Checklist | 检查清单 |
| Anti-Pattern | 反模式 |
| Rationalization | 合理化借口 |

## 翻译流程

### 1. 准备

```
遍历源目录 → 列出所有文件
分类：需翻译的 .md vs 需复制的脚本/代码文件
创建目标目录结构（镜像源目录）
原样复制脚本文件（.sh, .js, .ts, .cjs, .html, .dot）
```

向用户确认：
- 源目录路径（如 `skills/`）
- 目标目录路径（如 `skills-cn/`）
- 是否需要翻译 description 字段（推荐：是）
- 是否需要保留 name 字段为英文（推荐：是，程序标识符）

### 2. 并行翻译

按 skill 目录分组，每个目录分派一个 subagent。subagent 提示模板：

```
你的任务：将以下英文 markdown skill 文件翻译为中文。
开始翻译前，先读取 translate-skills/terms-to-keep.md 获取保留术语清单。

翻译规则：
1. 保留术语清单中的英文词，不翻译
2. 保留英文语义准确
3. 无中文对应词的保留英文
4. 专业术语首次出现时括号注明英文
5. 不翻译：代码块、命令、路径、YAML name 字段
6. 格式完整保留

源文件：[绝对路径列表]
目标路径：[对应绝对路径列表]
```

每个 subagent 提供该目录的全部文件内容。独立目录并行分派，单次分派建议不超过 5 个。

### 3. 并行审查

翻译完成后分派两类审查 subagent：

**A. 术语与格式审查：** 检查术语是否保留英文、代码块是否完整、YAML frontmatter 是否正确。

**B. 语义与一致性审查：** 对比原文检查错译/漏译/增译/歧义，以及跨文件的一致性。

逐文件输出审查结果，标注 `PASS` 或 `ISSUES` 及具体位置。

### 4. 修复

按严重程度修复审查发现的问题：

1. **严重**：错译、漏译、格式损坏 → 立即修复
2. **中等**：术语不当、语气弱化 → 修复并统一
3. **轻微**：文风偏好差异 → 视情况处理

每轮修复后用 `grep` 验证问题模式是否清除：

```bash
grep -rn "待修复模式" skills-cn/ --include="*.md"
```

### 5. 最终验证

- 文件数量与源目录一致
- `grep` 扫残留不一致模式
- 抽查核心 skill 完整可读性

## 常见问题与修复模式

| 问题 | 现象 | 修复方式 |
|------|------|---------|
| 术语过度翻译 | `子代理`、`竞态条件` | `sed` 全局替换为 `subagent`、`race condition` |
| "your human partner" 不一致 | 有的翻译、有的保留英文 | 统一为 `你的人类伙伴 (your human partner)` |
| Red Flags 标题不一致 | `红线`、`Red Flags` 混用 | 统一为 `红旗信号 (Red Flags)` |
| 铁律代码块遗漏 | 中文正文但代码块英文 | 翻译代码块内的标语文本 |
| 合理化借口表遗漏 | 表格某列保留英文 | 全文翻译该列 |
| YAML name 误翻译 | name 字段变为中文 | 恢复为英文原名 |
| description 未翻译 | description 仍为英文 | 翻译为中文 |
| 声明字符串未翻译 | "I'm using the ..." | 翻译为中文版本 |
| 错别字 | `推推断` → `推断` | 逐字修正 |

## 合理性边界

以下情况**不强制**统一：

- 测试压力场景文件中的英文对话——这些模拟真实 agent 交互，保留英文合理
- 外部参考文档（如 Anthropic 官方最佳实践）——超长文档不必全文翻译
- 代码块内的注释——可译可不译，不影响功能

## 快速参考

| 阶段 | 关键活动 | 验证方式 |
|------|---------|---------|
| 1. 准备 | 遍历分类、创建目录、复制脚本 | `find` 对比文件数 |
| 2. 并行翻译 | 按目录分派 subagent | 检查目标文件存在 |
| 3. 并行审查 | 术语 + 语义 + 一致性 | 审查报告 |
| 4. 修复 | 按严重程度批量修复 | `grep` 验证清除 |
| 5. 最终验证 | 文件数一致 + 抽查可读性 | 确认完成 |
